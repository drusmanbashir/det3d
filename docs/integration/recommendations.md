# RetinaUNet recommendations

Scope: the audited `lidca` plan 4 style configuration on the active `retinaunet` path. These findings do not establish how every historical checkpoint was built. No real-image inference, training, GPU run, or metric comparison was performed. See the pipeline detail in [planning](2-planning.md), [inference](6-inference.md), [training](5-training.md), and the existing [issue list](issues.md).

## Measured probes

The CPU probes used synthetic zero tensors and the active module constructor, with encoder channels reduced to 4/16 for a small run. They did not read patient data. `Encoder` consumes stride entry `stage_id - 1` for every stage after the first.

However, `encoder_abs_strides_from_plan()` returns only `[1,2,4,8]` for that list because it loops over `range(1, len(strides))`. Its callers use the last value for `size_divisible`; update this contract and callers together. Patch-divisibility failure was not tested. |

## Keep separate or defer

- **A6 padding:** investigate/fix reflection-padding consistency independently; do not bundle it into the training-recipe comparison.
- **Mask-derived boxes:** defer for genuine instance-mask datasets. The current eight-corner envelope is valid box-only augmentation; semantic masks cannot recover identities of touching lesions. See [augmentation](4-data-loading.md#46-boxes-after-augmentation).
- **Training/evaluation size rules:** do not force identical thresholds. The scorer ignores lesions under 3 mm, which may be deliberate. Review label mapping, connectivity, and size policy before changing either boundary; see [FROC](7-evaluation.md#73-froc).
- **Anchor fit and adaptive kernels:** test after the stride/level contract is sound, in separate runs. Do not infer that removing duplicate candidates alone preserves sensitivity.
