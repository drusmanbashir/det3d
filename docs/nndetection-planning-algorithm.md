# nnDetection planning algorithm and integration into det3d

This guide describes the **latest upstream main implementation checked on 2 November 2026**, specifically `D3V001` with `BoxC002` and `RetinaUNetV001`. Upstream main was at commit [`97a58f3110b71caf1b4bcc1851e67cf11e987fc5`](https://github.com/MIC-DKFZ/nnDetection/commit/97a58f3110b71caf1b4bcc1851e67cf11e987fc5); this is a source revision, not a new named algorithm version. The local checkout at `/home/ub/code/nnDetection` was at `09ff4ad`; its planning and preprocessing logic matches that upstream revision apart from local compatibility/scratch additions in `c002.py` and comments/docstrings in the working tree. The upstream implementations are [`D3V001`](https://github.com/MIC-DKFZ/nnDetection/blob/97a58f3110b71caf1b4bcc1851e67cf11e987fc5/nndet/planning/experiment/v001.py) and [`BoxC002`](https://github.com/MIC-DKFZ/nnDetection/blob/97a58f3110b71caf1b4bcc1851e67cf11e987fc5/nndet/planning/architecture/boxes/c002.py).

**Integration consequence:** current `det3d` training does not call nnDetection's dataset analyzer, planner, preprocessor, or data loader. Its optional RetinaUNet bridge uses nnDetection model code with architecture and anchors assembled by `det3d`; the default RetinaNet path does not use that model. The existing [LIDC configuration audit](/home/ub/code/det3d/docs/nndetection-config-audit-lidca.md) traces the actual bridge and every static model key. A saved nnDetection plan is evidence of what nnDetection chose for one dataset, not proof that `det3d` applied those choices.

## What is configured, calculated, and fixed

A **plan** is a saved dictionary of choices made for a dataset. A **dataset fingerprint** is the collected dataset statistics used to make those choices. These are distinct from the input configuration template.

| Source of value | Examples | How to change it |
|---|---|---|
| Hydra-composed configuration | `module`, `planner`, `model_cfg`, training, augmentation and prep settings in `/home/ub/code/nnDetection/nndet/conf/config.yaml` and `/home/ub/code/nnDetection/nndet/conf/train/v001.yaml` | Override the configuration when running nnDetection. Hydra combines configuration files and command-line overrides. |
| Python planner constants | spacing percentile 50, anisotropy thresholds 3, 3D start/max channels 32/320, batch 4, memory target | Change or replace the relevant planner/estimator code; these are not ordinary exposed YAML keys in this path. |
| Dataset-derived plan outputs | target spacing, transpose, convolution kernels and strides, patch size, class weights and anchors | Change the analyzed dataset or planning method and replan; they are written to a plan pickle. |
| Runtime overrides | `model_cfg.plan_arch_overwrites`, `model_cfg.plan_anchors_overwrites`; augmentation patch/batch overrides | Override the corresponding config field. A model override changes model construction; it does not automatically re-run preprocessing or reconcile the rest of the plan. |
| Post-training inference selection | model/ensemble suppression and score thresholds | Sweep validation predictions after training; this is separate from experiment planning. |

The input dataset contract and commands are described in the [official README](https://github.com/MIC-DKFZ/nnDetection/blob/main/README.md). In particular, analysis expects modality metadata and instance labels; the planner needs actual instance boxes, not only a semantic foreground mask with no recoverable instance identities.

## Spacing, orientation and normalization

| Decision | Exact rule and controlling function |
|---|---|
| Target spacing | `D3V001._target_spacing_base` in `/home/ub/code/nnDetection/nndet/planning/experiment/v001.py` takes the per-axis 50th percentile of spacings. If the worst-spacing axis is more than 3 times the finest other axis **and** its median voxel count times 3 is less than the smallest other axis, replace its spacing with that axis's 10th percentile, bounded just above the finest other spacing when necessary. The two tests must both hold. |
| Low-resolution spacing | `D3V001.determine_target_spacing` multiplies base spacing by 2 for `3dlr1`. This is a separate processed dataset and architecture plan. |
| Axis order | `D3V001.determine_forward_backward_permutation` puts the largest target-spacing axis first and stores both forward and inverse permutations. Arrays, spacings, boxes and later restoration must agree on the axis convention. |
| Resampled shape | `AbstractPlanner.plan_base_stage` calculates each cropped shape × original spacing / target spacing, then uses the per-axis median for architecture planning. |
| Normalization scheme | `AbstractPlanner.determine_normalization` chooses `CT`, `CT2`, or `nonCT` from modality names. `determine_whether_to_use_mask_for_norm` disables the nonzero mask for names containing `CT`; for other modalities it enables the mask if median crop-size ratio is below 0.75. Both are in `/home/ub/code/nnDetection/nndet/planning/experiment/base.py`. |
| Apply | `GenericPreprocessor.apply_process` transposes, resamples, then normalizes. `resample` uses image interpolation order 3 and segmentation order 0, with separate-axis behavior controlled by threshold 3 in `/home/ub/code/nnDetection/nndet/preprocessing/resampling.py`. CT clips at dataset foreground 0.5th/99.5th percentiles and uses dataset foreground mean/std; CT2 uses the same bounds but case-specific statistics; nonCT uses case mean/std, optionally inside the nonzero mask. Source: `/home/ub/code/nnDetection/nndet/preprocessing/preprocessor.py`. |

## How dataset values change the plan

The relationships below describe this planner's code, not a guarantee that changing one dataset measurement will change the final result: percentile boundaries, rounding, memory fitting and other inputs can leave an output unchanged.

| Dataset input | Calculated value | Effect on preprocessing or model |
|---|---|---|
| Number and identity of training cases | The analyzer aggregates the cases it finds into the fingerprint; its spacing, size, intensity and box statistics depend on their values, not simply the case count. | Adding cases can change the aggregate percentiles and therefore the resulting plan. Case count alone does not set network depth, width or batch size. `DatasetAnalyzer.analyze_dataset` in `/home/ub/code/nnDetection/nndet/planning/analyzer.py`. |
| Class dictionary and instance counts by class | `classifier_classes` and `seg_classes` are the number of classes; `class_weight` is computed from instance counts. | Changes model output dimensions. `class_weight` is saved but its consumption by `RetinaUNetV001` was not found. `BoxC002.process_properties` and `BoxC001.compute_class_weights` in `/home/ub/code/nnDetection/nndet/planning/architecture/boxes/c002.py` and `/home/ub/code/nnDetection/nndet/planning/architecture/boxes/base.py`. |
| Number and names of modalities | `in_channels` equals modality count; each name selects a normalization scheme. | Changes input channels and CT/CT2/nonCT processing. It does not choose `start_channels`, `max_channels`, FPN or head widths. `BoxC002.process_properties` and `AbstractPlanner.determine_normalization` in `/home/ub/code/nnDetection/nndet/planning/experiment/base.py`. |
| Per-case voxel spacing | Target-spacing percentile, optional anisotropy correction, axis order and rescaled shapes and boxes. | Controls image/label resampling and affects patch shape, per-axis kernels and strides, stage count and anchors. A coarse axis can be downsampled later and use kernel size 1. `D3V001._target_spacing_base`, `determine_forward_backward_permutation`, and `BoxC002._plan_architecture`. |
| Cropped image shapes and crop reductions | Median resampled shape; median crop-size ratio. | Shape bounds the initial patch and helps determine memory-fitting reductions and network depth; crop ratio controls non-CT normalization masking. `AbstractPlanner.plan_base_stage`, `determine_whether_to_use_mask_for_norm`, and `BoxC002._get_initial_patch_size`. |
| Lesion box dimensions and locations | Scaled and filtered box-size distribution; proxy maximum instances in a patch; 99.5th-percentile original box dimensions. | Box sizes drive optimized anchors, lesion density contributes to the memory estimate and potentially patch/depth, and the 99.5th-percentile test can trigger an additional low-resolution plan. `BoxC002._get_scaled_boxes`, `_estimte_num_instances_per_patch`, `_plan_anchors`, and `D3V001.trigger_low_res_model`. |
| Foreground voxel intensities | Sampled foreground mean, standard deviation and 0.5th/99.5th percentiles. | CT clipping and normalization change; these statistics do not directly select network depth or channel widths. `get_voxels_in_foreground`, `compute_stats`, and `GenericPreprocessor.normalize_ct`. |
| Any of the above | 3D `start_channels=32`, `max_channels=320`, `fpn_channels=head_channels=128`, `batch_size=4` remain planner defaults. | Network **stage count** can change with geometry and memory fitting, while these channel-width and batch defaults do not automatically adapt to the dataset. `BoxC001.create_default_settings` and `BoxC002.create_default_settings`. |

## Architecture, patch size and anchors

`D3V001.create_architecture_planner` instantiates `BoxC002` and `MemoryEstimatorDetection`. The following order matters: `BoxC001.plan` initializes defaults and reads the fingerprint, computes class weights, finds a patch and architecture that fit the memory estimate, then optimizes anchors. `BoxC001` is the parent implementation in `/home/ub/code/nnDetection/nndet/planning/architecture/boxes/base.py`.

| Choice | Mechanism and source |
|---|---|
| Input/output dimensions | `BoxC002.process_properties` sets `in_channels` from the number of modalities, `classifier_classes` and `seg_classes` from the class dictionary, and `dim` from the fingerprint. `compute_class_weights` uses per-class instance counts and saves `class_weight`; no consumption of that value was found in `RetinaUNetV001`, so do not assume it changes its loss. |
| Channels | `BoxC001.create_default_settings` sets 3D `max_channels=320`; `BoxC002.create_default_settings` sets `start_channels=32`, `fpn_channels=128` and `head_channels=128`. These widths are fixed defaults, not optimized from the dataset. The encoder uses the planned stage list and channel limits in `/home/ub/code/nnDetection/nndet/arch/encoder/modular.py`. |
| Initial patch | `BoxC002._get_initial_patch_size` uses inverse target spacing to form a roughly physically isotropic starting patch, scales it with a 512 starting factor, and clips it to the transposed median shape; for the two other axes it uses their smaller median dimension. This is a starting calculation, not the final patch. |
| Depth, kernels and strides | `BoxC002._plan_architecture` calls `BoxC001.plan_pool_and_conv_pool_late`, which calls nnUNet's `get_pool_and_conv_props` with spacing, current patch, minimum feature-map size 4 and maximum 999 pooling operations. Anisotropic axes can receive kernel size 1 and delayed downsampling. The resulting `conv_kernels` length is the number of encoder stages; `strides` specify downsampling. They change as spacing or the fitting patch changes. |
| Decoder levels | From the number of resolutions, `_plan_architecture` selects levels using `num_decoder_level=4` and `min_decoder_level=2`; the exact expression is `min(max(1, num_resolutions - 4), 2)` as the first selected level, through the final resolution. Thus it may select more than four levels. |
| Memory and final patch | The planner constructs the configured model and estimates training memory, including an estimate of instances per patch. It starts with 3D batch 4, and if the estimate does not fit, `_decrease_patch_size` reduces the axis with the largest patch/median-shape ratio, replans kernels/strides, and repeats. Batch size is fixed here; this loop changes patch size, not batch. The estimator defaults in `/home/ub/code/nnDetection/nndet/planning/estimator.py` target `RTX2080TI` (11,523,260,416 minus 11 MiB bytes), GPU 0, 910 MiB context, 768 MiB offset and mixed precision. The estimator measures on an actual GPU and estimates against this fixed target unless the estimator is changed; it is not a guarantee for a different GPU or software stack. |
| Anchors | `BoxC002._get_scaled_boxes` transposes boxes and scales them from each original spacing into target-spacing voxels. `BoxC001.filter_boxes` strictly excludes sizes at or outside the 0.5th and 99.5th percentile on each axis. `BoxC002._plan_anchors` and `BoxC001.find_anchors` center these boxes and use three Nevergrad `TwoPointsDE` runs, budget 5,000 each, to maximize mean best box–anchor intersection over union. Initial sizes are `(4, 8, 16)` per axis, integer and at least 1; feature-level strides scale the resulting anchor parameters. This path calls CUDA. |
| Additional low-resolution plan | `D3V001.trigger_low_res_model` computes per-axis 99.5th-percentile box sizes from the stored original boxes, permutes them, and triggers if any exceeds the full-resolution patch dimension. The code compares these stored box voxel sizes directly with the planned patch; do not silently assume it first rescales them to target spacing. |
| Dummy 2D augmentation | `AbstractPlanner.plan_base_stage` sets `do_dummy_2D_data_aug` when largest/smallest patch dimension is strictly greater than 3. This controls augmentation geometry; it does not make the model 2D. |

The plan records `target_spacing`, `target_spacing_transposed`, `transpose_forward`/`transpose_backward`, normalization and mask decisions, dataset properties, `patch_size`, `batch_size`, `architecture`, `anchors`, `data_identifier`, and `do_dummy_2D_data_aug`. For reproducibility retain the fingerprint, plan, input configuration, dataset identity, and source/dependency versions together. Changes to spacing, transpose or patch convention require coordinated changes to image preprocessing, box coordinates and inference restoration.
